## 1. 目标与边界

### 1.1 要达成的

- 任意两种受支持格式之间双向转换（A→B 与 B→A 都成立），用户只需选「目标格式」。
- 转换能力与**保真等级**对用户可见，不假装所有转换都无损。
- 保持 1.0 的三条底线：`txt → md` 输出不变、中文编码自动识别、单文件失败不中断批量。
- 核心转换不依赖任何外部程序；外部引擎只做可选增强。

### 1.2 明确不承诺的

| 不承诺 | 原因 |
| --- | --- |
| PDF → DOCX 的版式还原 | 唯一成熟方案 `pdf2docx` 依赖 PyMuPDF（AGPL-3.0），会传染本项目分发许可 |
| 扫描件 PDF 的识别 | 需要 OCR 模型，与单文件发布形态冲突 |
| xlsx 的公式/图表/条件格式保真 | 只搬运值与数字格式；公式转静态值 |
| docx 的页眉页脚、脚注、分栏 | 块模型里没有对应结构，读取时丢弃 |
| 图片跨格式搬运 | 只在 docx 内原样留存，导出到其它格式时丢弃（README 保真边界表已写明） |

### 1.3 保真分级

| 记号 | 名称 | 含义 |
| --- | --- | --- |
| **●** | 结构保真 | 标题/列表/表格/强调等语义元素完整往返，样式简化 |
| **◐** | 内容保真 | 文字与表格内容完整，层级/样式需重建或丢失 |
| **○** | 纯文本 | 只保证字符顺序，结构从零推断 |

## 2. 格式矩阵

7 种格式：`txt` `md` `html` `csv` `xlsx` `docx` `pdf`，**42 个有向组合**。

下表是本机（Windows 11 + Edge）实测结果，即 `txt2md --formats` 的输出：

| 从 ＼ 到 | txt | md | html | csv | xlsx | docx | pdf |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **txt** | · | ● | ◐ | ● | ● | ◐ | ◐ |
| **md** | ● | · | ◐ | ● | ● | ◐ | ◐ |
| **html** | ◐ | ● | · | ◐ | ◐ | ◐ | ◐ |
| **csv** | ● | ● | ◐ | · | ● | ◐ | ◐ |
| **xlsx** | ● | ● | ◐ | ● | · | ◐ | ◐ |
| **docx** | ◐ | ● | ◐ | ◐ | ◐ | · | ◐ |
| **pdf** | ○ | ○ | ○ | ○ | ○ | ○ | · |

读法：`md → xlsx` 保真 ●（结构表可还原）；`pdf → md` 只有 ○（文本层重排，标题靠字号猜）。

**矩阵是运行时算出来的**，不是常量表：`pdf` 的写出依赖浏览器或 pandoc+LaTeX，
`docx`/`xlsx` 的读写依赖各自的库。缺什么就在矩阵里标为不可用，GUI 里置灰并说明
原因——不让人点了才失败。

## 3. 架构

### 3.1 主链路

```
CLI / GUI
   │  用户意图：源文件 + 目标格式
   ▼
pipeline.plan_jobs()      # 收集文件、规划目标路径、同名冲突自动改名
   ▼
pipeline.check()          # 逐项防呆：自毁/0 字节/二进制/目录不可写/无能力…
   ▼
pipeline.convert_one()
   │   ① 源格式 == 目标格式 → 逐字节复制（不重新排版）
   │   ② txt → md            → 走 1.0 直通通道（字节级一致）
   │   ③ 其余                → 读取器 → 模型 → 写出器
   │                              ↓ 失败且非防呆拦截
   │                           pandoc 兜底（可选）
   ▼
pipeline.verify_output()  # 产物校验：非空/有效 UTF-8/魔数正确/源有内容产物不能空白
   ▼
Result(ok | skipped | error(人话原因))
```

### 3.2 双载荷模型

关键决策：**M×N 转换降为 M 读 + N 写**。所有格式先读成统一模型，再由写出器渲染。

| 载荷 | 形态 | 服务于 |
| --- | --- | --- |
| `TextDoc` | `list[Block]`，块类型含 heading / paragraph / list / code / quote / table / divider / raw | txt / md / html / docx / pdf 的文本类转换 |
| `Workbook` | `list[Sheet]`，`Sheet = 名称 + list[list[str]]` | xlsx / csv 表格类转换 |

`Document` 同时持有两者，由 `kind`（`"text"` / `"table"`）决定走哪条路径。
`Workbook` 可以退化成 `TextDoc`（表格 → Markdown 表格），反向则靠**结构表**：
`TextDoc` → `Workbook` 时，表格块各自成表，其余内容进 `_txt2md_body` 工作表，
用 `[类型, 层级, 内容]` 三列记住块类型和层级——这样 `md → xlsx → md` 能还原
标题级别、列表层级、代码语言，而不是把文章拍平成几行字。

**为什么不用通用 AST**：块序列已经够用，且 1.0 的排版规则就是围绕 Markdown 文本
工作的，`TextDoc` 能直接复用。再抽象一层只会增加映射成本。

### 3.3 模块划分

```
core/
├─ model.py       Block / Sheet / TextDoc / Workbook / Document；双载荷转换
├─ mdparse.py     GFM 块级解析（ATX/Setext 标题、嵌套列表、围栏代码、引用、表格）
├─ htmlio.py      标准库 HTMLParser 提取块；render_html（含 @page 打印 CSS）
├─ registry.py    格式表、引擎探测、能力矩阵
├─ readers.py     7 个读取器 + 编码打分 + 二进制识别
├─ writers.py     7 个写出器 + 原子写入
├─ pipeline.py    Job / 预检 / 执行 / 产物校验 / 汇总
├─ legacy.py      1.0 排版算法原样保留（txt → md 直通）
├─ pandoc_fallback.py  可选兜底通道
└─ errors.py      分层异常：ConvertError / EngineMissing / SourceError / …
gui/
├─ app.py         主窗口、转换线程、预检结果呈现
├─ widgets.py     Fluent 控件与格式胶囊
└─ theme.py       颜色令牌与 QSS
```

纪律：`readers.py` / `writers.py` 只依赖 `model.py` 与 `errors.py`；
`pipeline.py` 是唯一碰文件系统与决策的地方；GUI 只调用 `pipeline`，不直接读格式。

### 3.4 防呆清单

| 检查 | 时机 | 行为 |
| --- | --- | --- |
| 源不存在 / 是目录 | 预检 | 拒绝，不计入任务 |
| 源为 0 字节 | 预检 | 拒绝并说明 |
| 源与目标是同一个文件 | 预检 | 拒绝（防止自我覆盖成空） |
| 无法识别源格式 | 预检 | 拒绝，列出支持的扩展名 |
| 目标目录不存在 | 预检 | 自动创建；不可写则拒绝 |
| 缺依赖导致目标不可写 | 预检 | 拒绝并给出安装命令 |
| 目标已存在 | 预检 | 默认跳过，`--force` 才覆盖 |
| 批量中目标重名 | 规划 | 自动加 ` (2)` 后缀 |
| 二进制文件伪装成 .txt | 预检 + 执行 | 识别文件头并拒绝解码 |
| 写入中断 | 执行 | 临时文件 + `os.replace`，不留半成品 |
| 产物为空/伪 PDF/坏 zip | 校验 | 判为失败而非成功 |
| 终端编码写不出符号 | 启动 | 符号降级为 ASCII，不崩 |

## 4. 选型结论

| 能力 | 方案 | 分发 | 许可 |
| --- | --- | --- | --- |
| txt / md / html / csv | 自研（纯标准库） | 打进 exe 与 wheel | MIT |
| xlsx | `openpyxl` | 同上 | MIT |
| docx | `python-docx` | 同上 | MIT |
| pdf 读 | `pdfplumber` + `pdfminer.six` | 同上 | MIT |
| pdf 写 | Edge / Chrome `--headless --print-to-pdf` | 调用系统已有浏览器 | 不涉及分发 |
| 编码探测兜底 | `charset-normalizer` | 同上 | MIT |
| 兜底转换 | pandoc（`pypandoc-binary`） | **可选，默认不装不打包** | 独立进程调用 GPL 程序，不传染 |

**不引入**：PyMuPDF（AGPL）、LibreOffice（500 MB+ 且未实测）、markitdown（单向）、
gotenberg（需要 Docker）。

## 5. 接口

### 5.1 命令行

1.0 的全部参数保留，新增：

| 参数 | 作用 |
| --- | --- |
| `--to` / `-t` | 目标格式（默认 md，与 1.0 行为一致） |
| `--from` / `-f` | 强制源格式（默认按扩展名判断） |
| `--force` / `--overwrite` | 覆盖已存在的目标 |
| `--plain` | 逐字保真，不加任何 Markdown 标记 |
| `--encoding` | 强制指定源编码 |
| `--sheets` | 只转换指定工作表 |
| `--dry-run` | 只预检并列出计划，不动文件 |
| `--formats` | 打印能力矩阵 |
| `--engines` | 打印本机可用引擎 |
| `--no-verify` | 跳过产物校验 |
| `-q` / `--quiet` | 只输出汇总 |

退出码：`0` 全部成功，`1` 有失败，`2` 参数/输入错误。

### 5.2 图形界面

- 格式胶囊选择器，按 `capability()` 置灰，工具提示写明保真等级与所用引擎。
- 源文件类型变化时自动建议目标格式（不与源格式撞车）。
- 转换前先预检，被拦的项目当场入日志，不等转换时才报错。
- 全部成功不弹模态框（界面上已有汇总），只在有失败时打断。

## 6. 关键实现细节

### 6.1 编码探测

顺序：BOM → UTF-8 → charset-normalizer → 候选中文编码打分。

GBK 与 Big5 的高位区重叠，1.0 按顺序先命中 GBK，会把繁体文件解成乱码。现在对
每个候选解码结果打分：

```
得分 = (常见汉字数 × 3 + 汉字总数) / 总长 − (控制字符+替换符) × 40 / 总长
```

取最高分。1.0 已正确解出的文件结果不变（UTF-8 命中后不再往下试）。

### 6.2 行内标记剥离

中文紧贴 `**粗体**` 时，`(?<![\w*])` 会失效——**Python 的 `\w` 默认包含中文**。
所有边界判断改用 `[A-Za-z0-9_]`。`mdparse.py` 和 `htmlio.py` 里都有注释防止改回去。

### 6.3 空行策略

`render_markdown` 在块**之前**补空行（而不是之后）：块之后的写法在「嵌套层回到
外层」时会漏掉分隔。列表层级发生变化时视为续接，不插空行——否则一个列表会被
GFM 判成两个 loose list。

### 6.4 xlsx 数值精度

写的时候同时写 `number_format`，读的时候按格式还原小数位。否则 `12.50` 往返会
变成 `12.5`。`007` 这类前导零用文本形式写入，不会被吃成 `7`。

### 6.5 PDF 读取

PDF 没有「表格」「列表」「标题」这些概念，只有字符和坐标。处理顺序：

1. `find_tables()` 找表格候选。**先把全空的列裁掉**——整页被误判成表格时，右边
   那列是所有行都空的假列。裁完只剩一列就不是表格。
2. 表格框高度占页面 75% 以上判为虚警（HTML 打印件里 `h1` 下划线、代码块和表格
   边框会连成整页网格），退回「整页当正文」。**宁可丢表格结构，也不能让整篇
   文章塌成一张表、内容还重复两遍。**
3. 有表格时按表格把页面切成水平带，带内取正文、表格位置放表格，保证顺序正确
   且不重复提取。
4. 表格以外：字号比正文大 15% 以上的行当标题（按字号降序映射 h1/h2/h3）；
   左缩进差当作列表层级；行尾标点决定段落边界。

### 6.6 PDF 写出

`TextDoc → render_html（带 @page 与分页避断 CSS）→ 浏览器 --print-to-pdf`。
**不信任进程退出码**：写完检查文件头是否为 `%PDF` 且大小合理，否则判失败。
浏览器参数含 `--virtual-time-budget=8000`，避免打印时字体还没加载完。

### 6.7 原子写入

`tempfile.mkstemp` 建同目录临时文件 → 写入 → `os.replace` 覆盖。中途任何失败
都不会留下半个损坏的目标文件。

## 7. 实现顺序（已完成）

1. 模型与解析：`model.py`、`mdparse.py`、`errors.py`
2. 读：`readers.py`（7 个读取器 + 编码打分）
3. 写：`writers.py`（7 个写出器 + 原子写入）
4. 编排：`pipeline.py`（预检、执行、校验、汇总）
5. 兼容：`legacy.py` 接管 `txt → md`，确保 1.0 输出不变
6. 界面：格式胶囊、能力置灰、预检呈现
7. 测试：内核 87 项 + 界面 14 项
8. 打包：PyInstaller 单文件 + wheel

## 8. 风险与对策

| 风险 | 现状 |
| --- | --- |
| 保真度被高估 | `--formats` 打印真实等级；README 列了「保留/不保留」两张表 |
| 依赖变多导致体积膨胀 | 无 PySide6 时 CLI 仍可用；exe 从 36 MB 增至 119 MB，已在发布说明中写明 |
| 浏览器不可用导致 PDF 写出失败 | 能力矩阵标为不可用，GUI 置灰，命令行提前拦截 |
| 兜底通道绕过防呆 | pandoc 兜底前检查异常类型，二进制/空文件不交给它 |
| 终端编码导致崩溃 | 启动时装输出流守卫（cp936 下 `◐` 会抛 `UnicodeEncodeError`） |

## 9. 与初版规划的差异

| 初版规划 | 实际实现 | 原因 |
| --- | --- | --- |
| 42 条各自实现的转换边 | 7 读 + 7 写 = 统一模型 + 多导出器 | 42 条边各自为政会导致同一文档在不同路径下结构判断不一致，测试量也是 42×N |
| LibreOffice 兜底 office → pdf | 完全未采用 | 本机无法实测（证据层级 1）、500 MB+、MPL 分发义务；改用 HTML + Edge 打印 |
| Word COM 备用通道 | 完全未采用 | 只有 Windows 有 Word 时可用，覆盖面太窄 |
| pandoc 作为「可选引擎」承担 docx/html 读写 | 降为失败兜底，默认不装 | xlsx 只读不能写、PDF 输出要 LaTeX、对 xlsx 生成器敏感 |
| `TextDoc = Markdown 字符串 + 资产` | `TextDoc = list[Block]` | 字符串无法承载块结构，往返时层级信息会丢 |
| `convert/` 目录 + Router 规划 | `core/` + pipeline 直接按格式分派 | 有统一模型后不存在「多跳路由」，Router 这层没有存在意义 |

## 10. 与 1.0 的兼容性

- `txt2md note.txt` 仍输出 `note.md`；`--plain` 仍为逐字保真。
- 1.0 的排版算法原样保留在 `core/legacy.py`，作为 `txt → md` 的直通通道，
  输出与 1.0 **字节级一致**（`tests/test_convert.py` 有对应断言）。
- 1.0 的公开 API 保持可用：`convert_file` / `collect_txt_files` / `run_convert` /
  `read_text_smart` / `to_markdown`。
- 唯一变化是依赖不再为零：xlsx / docx / pdf 分别需要 openpyxl / python-docx /
  pdfplumber，缺哪个只少一种格式。
