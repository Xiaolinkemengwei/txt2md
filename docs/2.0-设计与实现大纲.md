# txt2md 2.0 设计与实现大纲

> 目标版本：2.0.0 · 主题：从「txt → md 一条边」升级为「多格式有向图」
> 配套调研：[research/2026-11-07-2.0-多格式互转调研.md](../research/2026-11-07-2.0-多格式互转调研.md)

---

## 1. 目标与边界

### 1.1 要达成的

- 任意两种**受支持格式**之间双向转换（A→B 与 B→A 都成立），用户只需选「目标格式」。
- 转换路径与**保真等级**对用户可见，不假装所有转换都无损。
- 保持 1.0 的三条底线：命令行零第三方依赖可跑、中文编码自动识别、单文件失败不中断批量。
- 引擎（pandoc / LibreOffice / Word）**全部可选**：有则用，无则降级并明示。

### 1.2 明确不承诺的

| 不承诺 | 原因 |
|---|---|
| PDF → DOCX 的版式还原 | 唯一成熟方案依赖 PyMuPDF（AGPL-3.0），会传染本项目分发许可 |
| 扫描件 PDF 的识别 | 需要 OCR 模型，与「35 MB 单文件」的量级冲突 |
| xlsx 的样式/公式/图表完整保真 | 转换层只搬运值、维度与基础格式；公式转静态值 |
| docx 的浮动元素精确定位 | 文本框、环绕图片在 Markdown 里无对应语义 |

### 1.3 保真分级（贯穿 UI 与文档的术语）

| 记号 | 名称 | 含义 |
|---|---|---|
| **●** | 结构保真 | 标题/列表/表格/强调等语义元素完整往返，样式简化 |
| **◐** | 内容保真 | 文字与表格内容完整，层级/样式需要重建或丢失 |
| **○** | 纯文本 | 只保证字符顺序，结构从零推断 |

## 2. 格式矩阵

支持 7 种格式：`txt` `md` `html` `docx` `xlsx` `csv` `pdf`，共 **42 条有向边**。

单元格 = 实现方式 + 保真等级。缩写：**原生**=自研编解码，**PD**=pandoc，**LO**=LibreOffice，**ED**=Edge/Chromium 无头，**WD**=Word COM，**PL**=pdfplumber。

| 从 ＼ 到 | txt | md | html | docx | xlsx | csv | pdf |
|---|---|---|---|---|---|---|---|
| **txt** | — | 原生 ● | PD ● | PD ◐ | 原生 ◐ | 原生 ● | ED ◐ |
| **md** | 原生 ● | — | PD ● | PD ◐ | 原生 ◐ | 原生 ◐ | ED ◐ |
| **html** | PD ◐ | 原生 ● | — | PD ◐ | 原生 ◐ | 原生 ◐ | ED ● |
| **docx** | PD ◐ | PD ◐ | PD ◐ | — | PD ◐ | PD ◐ | LO ● → WD ● |
| **xlsx** | 原生 ● | 原生 ◐ | 原生 ◐ | PD ◐ | — | 原生 ● | LO ◐ |
| **csv** | 原生 ● | 原生 ● | PD ● | PD ◐ | 原生 ● | — | ED ◐ |
| **pdf** | PL ● | PL ◐ | PL ◐ | ◐ 文本重排 | ○ | ○ | — |

读法示例：`docx → pdf` = 优先 LibreOffice，缺失时退 Word COM，保真 ●；`pdf → md` = pdfplumber 提取文本层后重建 Markdown，保真 ◐。

**矩阵不是静态常量**：启动时按实际探测到的引擎裁剪，界面上不可达的目标格式直接灰化并给出安装提示。

## 3. 架构

### 3.1 主链路

```
CLI / GUI
   │  用户意图：源文件 + 目标格式（+ 可选引擎、覆盖策略）
   ▼
Job(from, to, src, dst, engine_hint)
   │
   ▼
Router.plan()  ──► Route(edges=[…], fidelity, reason)
   │   ① 有直接边 → 直接用（最短、最高保真）
   │   ② 无直接边 → 经枢纽（TextDoc 或 Workbook）两跳
   │   ③ 都不通 → Unreachable(缺失引擎名)
   ▼
Runner.execute()  ──► 临时目录 / 超时 / 错误归一 / 清理
   │
   ├─ 原生边（进程内函数调用）
   └─ 引擎边（subprocess → pandoc / soffice / msedge / Word）
   ▼
ConvertResult(ok | skipped | failed(错误码, 人话原因))
```

### 3.2 两个枢纽（IR）

不自造通用 AST——成本高且收益低。用两个贴近实际语义的中间表示：

| 枢纽 | 形态 | 服务于 |
|---|---|---|
| `TextDoc` | GFM 字符串 + 资产目录（图片、附件） | txt / md / html / docx / csv 之间的文本类转换 |
| `Workbook` | `list[Sheet]`，`Sheet = 名称 + list[list[Cell]]` | xlsx / csv / md 表格 |

理由：1.0 的全部逻辑已经围绕 Markdown 文本工作，`TextDoc` 可直接复用 `to_markdown` 的排版规则；而 xlsx 是**多工作表二维结构**，硬塞进 Markdown 会丢 sheet 维度，必须单列。

跨枢纽（`xlsx → docx`）= `Workbook → TextDoc`（每个 sheet 一张表 + 标题）→ pandoc。

### 3.3 模块划分

```
convert/
├─ formats.py     # FormatSpec：扩展名、MIME、可读写性、需要的引擎、保真表
├─ ir.py          # TextDoc / Workbook / Table 及互转
├─ router.py      # 路由规划（直接边 / 枢纽 / 不可达），纯函数、可单测
├─ runner.py      # 任务执行：临时目录、超时、并发、错误归一
├─ engines.py     # 能力探测与缓存（版本号、路径、可用格式集合）
├─ errors.py      # 错误码枚举 + 中文文案
└─ edges/
   ├─ native_text.py   # txt / md / html 读写（复用 1.0 的编码与排版规则）
   ├─ native_table.py  # csv / xlsx 读写（openpyxl）
   ├─ pandoc.py        # 文本格式互转（不含 xlsx、不含 pdf 输出）
   ├─ libreoffice.py   # office → pdf，office ↔ office
   ├─ browser.py       # html → pdf（Edge / Chrome 探测）
   ├─ word.py          # docx → pdf（Word COM，备用）
   └─ pdftext.py       # pdf → txt/md（pdfplumber）
```

纪律：`edges/*` 只依赖 `ir.py` 与 `errors.py`；`router.py` 不碰文件系统；`txt2md.py` 保留 1.0 全部函数签名，`convert_file` 改为薄封装调用新链路。

### 3.4 路径规划规则

1. **直接边优先**：`docx → pdf` 走 LibreOffice，不经 Markdown（避免两次有损）。
2. **枢纽优先选无损侧**：`xlsx → md` 走 `Workbook → TextDoc`；`md → xlsx` 反向。
3. **同一对格式有多条边时按保真降序**：`docx → pdf`：LO(●) → WD(●) → PD(pdf 引擎缺失则跳过)。
4. **不存在的边直接报错，不做「看起来像成功」的兜底**（例如 `pdf → xlsx` 只给 ○，UI 上标注「仅文本」）。

## 4. 选型结论（详见调研报告）

| 能力 | 方案 | 分发方式 | 许可处理 |
|---|---|---|---|
| txt / md / html / csv / xlsx | 自研 + `openpyxl` | 打进 wheel 与 exe | MIT |
| 文本格式大家族（docx/odt/pptx/epub/rst…） | pandoc | **不捆绑**，探测用户环境或引导安装 | 独立进程调用，不传染 GPL |
| office → pdf 版式保真 | LibreOffice headless → Word COM | 探测已安装 | MPL-2.0，不打包 |
| md/txt/html → pdf | Edge/Chromium `--print-to-pdf` | 系统自带 | 零成本 |
| pdf → 文本 | pdfplumber | 打进 wheel | MIT |
| ~~markitdown / gotenberg / unoconv / pdf2docx / PyMuPDF~~ | 不采用 | — | 方向单一 / 需 Docker / 已归档 / AGPL 传导 |

exe 体积预算：核心 + `openpyxl` + `pdfplumber`（含 pdfminer.six）约 **+8 MB**，总量控制在 **45 MB 内**；pandoc 若捆绑会 +30 MB 且引入 GPL 义务，因此坚持外置。

## 5. 接口变更

### 5.1 命令行（1.0 全部保留）

```bash
txt2md notes/                      # 1.0 行为不变：→ md
txt2md notes/ --to md              # 显式等价写法
txt2md notes/ --to pdf             # 新增：批量转 PDF
txt2md notes/ --to md docx pdf     # 新增：一次跑多目标
txt2md a.pdf --to md               # 新增：反向
txt2md engines                     # 新增：打印引擎探测结果 + 可达矩阵
```

新增参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--to FMT...` | `md` | 目标格式，可多个 |
| `--from FMT` | `auto` | 源格式（默认按扩展名推断） |
| `--engine E` | `auto` | 强制指定引擎（`pandoc`/`libreoffice`/`browser`/`word`/`native`） |
| `--fail-fast` | 关 | 遇错立即终止（默认沿用 1.0 的「跳过继续」） |

`--smart` / `--plain` / `-o` / `--overwrite` / `--version` 语义不变；`--smart` 仅在 `→ md` 时生效。

### 5.2 图形界面

- 「转换选项」卡片升级为三块：**目标格式**（多选下拉，能力感知灰化）、**智能排版**（仅 md 目标可见）、**覆盖已存在**。
- 每行日志新增「路径」与「保真」两列：`报告.docx → LibreOffice → 报告.pdf  ●`
- 顶部横幅：引擎探测摘要（如「已检测：pandoc 3.9 / Edge；未检测到 LibreOffice —— docx→pdf 将不可用」），点击展开安装指引。
- 批量矩阵：N 个文件 × M 个目标格式，进度按「文件×目标」计数。

## 6. 关键实现细节

| 关注点 | 做法 |
|---|---|
| 临时目录 | 每次任务 `tempfile.mkdtemp(prefix="txt2md-")`，`finally` 清理；引擎子进程的 `-env:UserInstallation` 指向其中 |
| 超时 | 原生边 30 s，外部引擎 120 s（可配）；超时归为 `TIMEOUT` 并杀进程树 |
| 并发 | 外部引擎任务并发上限 2（LibreOffice 并发易锁），原生边顺序执行即可 |
| 错误归一 | `ENGINE_MISSING` / `PARSE_FAILED` / `ENCRYPTED` / `TOO_LARGE` / `TIMEOUT` / `UNSUPPORTED` 六类，UI 显示人话 + 展开原始 stderr（截断 2 KB） |
| 安全 | 拒绝 >100 MB 输入；zip 型（docx/xlsx）解压前后比检测；不执行宏；PDF 不解析 JS |
| 编码 | 输出统一 UTF-8；`txt → *` 复用 1.0 的 BOM→UTF-8→Big5→GBK 探测链 |
| 命名 | 源主干名 + 目标扩展名；同名冲突按 `--overwrite` 处理，未开启则记 `skipped` |
| 幂等 | 同一任务重复执行结果一致；临时文件名带随机后缀避免互相覆盖 |

## 7. 开发阶段划分

| 阶段 | 内容 | 交付物 | 验收标准 | 估时 |
|---|---|---|---|---|
| **P0 能力探测** | `engines.py`、`formats.py`、`txt2md engines` | 探测报告 | 本机输出 pandoc 3.9 / Edge 可用、LibreOffice 缺失；探测耗时 <300 ms | 0.5 周 |
| **P1 原生编解码** | txt/md/html/csv/xlsx 双向 + 1.0 回归 | `edges/native_*` | 1.0 全部用例逐字节不变；5 格式互转矩阵通过 | 1 周 |
| **P2 pandoc 适配** | docx/odt/pptx/epub/html；格式名映射；缺失降级 | `edges/pandoc.py` | md↔docx 往返结构保真（标题/列表/表格）；无 pandoc 时给出可操作提示 | 1 周 |
| **P3 PDF 输出链** | ED → LO → WD 优先级链 + docx/xlsx 直转 | `edges/browser.py`、`libreoffice.py`、`word.py` | md/docx/xlsx → pdf 均产出可打开文件；中文不乱码 | 0.5 周 |
| **P4 PDF 输入** | pdfplumber 文本层 + 标题启发式 | `edges/pdftext.py` | 文本型 pdf→md 有层级；扫描件明确报「无文本层」 | 0.5 周 |
| **P5 界面与打包** | 目标格式多选、能力灰化、路径/保真列、引擎横幅 | `gui/`、`txt2md.spec` | 4 尺寸截图回归通过；exe ≤45 MB 且启动正常 | 1 周 |
| **P6 质量门禁** | 7×7 矩阵脚本、错误注入、大文件 | `tests/test_matrix.py` | 42 条边全部有结果（成功或明确失败）；CI 全绿 | 0.5 周 |

合计约 **5 周**。P0/P1 不可并行压缩（后续全部依赖注册表）；P3 与 P4 可并行。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 用户把「支持互转」理解为「无损互转」 | 口碑反噬 | 矩阵与 UI 都标保真等级；文档给「同一格式往返会丢什么」的具体例子 |
| LibreOffice/Word 缺失导致主力场景不可用 | 核心功能残废 | Edge 覆盖文本类→pdf；文档明确「装 LibreOffice 获得 office→pdf」；提供绿色版路径配置 |
| pandoc 版本差异（老版本格式名不同） | 调用失败 | 探测版本，<3.0 时把 `md` 映射为 `markdown`、禁用 `gfm` 特有特性 |
| 外部进程挂死 | 界面卡死 | 超时 + 杀进程树 + 单任务隔离，不阻塞 UI 线程 |
| 许可误用 | 法律风险 | CI 加依赖白名单检查，禁止 `pymupdf`/`pdf2docx` 进入依赖树 |
| 大文件内存爆 | 崩溃 | 100 MB 上限 + 流式写；xlsx 用 `read_only=True` |

## 9. 与 1.0 的兼容性

- `txt2md <路径>` 不带 `--to` 时，行为与 1.0 **完全一致**（→ md，智能排版，跳过已存在）。
- `txt2md.importable` API 保留 `read_text_smart` / `to_markdown` / `convert_file` / `collect_txt_files` 四个符号。
- 配置文件（若后续加入 `~/.txt2md.toml`）不影响 1.0 用法；无配置时全部走默认值。
- 升级路径：用户无需迁移，旧命令照常工作；`--to` 是纯增量。
