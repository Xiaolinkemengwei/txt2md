## 1. 项目简介

**txt2md** 是一个本地运行的文档格式转换工具。名字保留自 1.0（当时只做 TXT → Markdown），
2.0 起支持 7 种格式的双向互转。

### 要解决的问题

日常遇到的真问题通常不是「转不了」，而是这几类：

| 现象 | 根因 |
|---|---|
| 老 `.txt` 打开是乱码 | 中文 Windows 记事本默认 GBK，现代工具默认按 UTF-8 读 |
| 转了格式，内容少了一截 | 转换器遇到「不认识的结构」就默默丢弃 |
| 批量转完，文件被覆盖了 | 多个源文件产出同名目标，或者输出到了源目录 |
| 转了一半报错，留下坏文件 | 直接往目标路径写，失败时不清理 |
| 明明有 PDF 选项，点了就失败 | 缺 LaTeX / Office，但工具没提前说 |

2.0 的设计基本就是逐条对着这些来的：**先保证不弄坏东西，再谈转得好不好看**。

### 适用人群

- 需要把一批笔记 / 文档在 Markdown、Word、PDF 之间倒腾的人
- 希望脚本化批量转换，不想为此装 pandoc + LaTeX + Office 的人
- 处理中文文档，对编码和数值精度敏感的场景

### 设计立场

1. **内置优先**。核心格式的读写全部自己实现（基于 openpyxl / python-docx / pdfplumber
   这类纯 Python 库），不把 pandoc 设为必需依赖。理由见第 7.3 节。
2. **保真可验证**。所谓「无损」必须能被测试断言，不能只是宣传语。第 8 节列了具体断言。
3. **失败要吵**。宁可拒绝执行，也不要产出「看起来成功了」的坏文件。

## 2. 功能特性

### 2.1 格式与转换方向

| 格式 | 读 | 写 | 读实现 | 写实现 | 保真 |
|---|:--:|:--:|---|---|---|
| `txt` | ✓ | ✓ | 内置编码探测 | 内置 | 逐字 |
| `md` | ✓ | ✓ | 内置 GFM 块解析 | 内置 | 结构完整 |
| `html` | ✓ | ✓ | 标准库 HTMLParser | 内置（含打印样式） | 内容完整 |
| `csv` | ✓ | ✓ | 标准库 csv（自动判分隔符） | 标准库 csv | 逐格 |
| `xlsx` | ✓ | ✓ | openpyxl | openpyxl | 逐格 |
| `docx` | ✓ | ✓ | python-docx（含 run 级格式） | python-docx | 结构完整 |
| `pdf` | ✓ | ✓ | pdfplumber | 无头浏览器打印 | 文本层重排 |

7 格式 × 6 目标 = **42 个有向组合**，测试会逐个跑一遍（第 8.2 节）。

### 2.2 转换能力

- **批量**：整目录递归，按扩展名白名单收集；保留相对目录结构
- **编码自动识别**：BOM → UTF-8 → GB18030 → Big5 → charset-normalizer 兜底
- **简繁歧义消解**：对候选解码结果做文本合理性打分，避免 GBK 吞掉繁体文件
- **多工作表**：xlsx 每个 sheet 独立处理，可指定只转某几个
- **单元格精度**：前导零保持文本，小数位数按 `number_format` 还原
- **同格式安全**：源与目标格式相同时逐字节复制，不重新排版

### 2.3 界面

Fluent Design 原生桌面应用（PySide6）：

| 元素 | 实现 |
|---|---|
| 配色 | Fluent 2 亮色：`#F3F3F3` 底 + 白卡片 + `#0F6CBD` 强调色 |
| 字体 | 运行时探测 Segoe UI Variable → Segoe UI → 微软雅黑；图标用 Segoe Fluent Icons |
| 层级 | 卡片 8px 圆角 + 1px 描边 + 20px 模糊投影 |
| 格式选择 | 胶囊按钮组，按本机引擎能力置灰并附原因 |
| 反馈 | 逐条日志（含失败原因）、进度条、汇总；预检拦截项在动手前就列出 |
| 适配 | 全弹性布局 + 文本省略；最小 720×660，实测至 1120×1000 无挤压 |

## 3. 安装与使用

### 3.1 三种安装方式

**下载可执行文件（Windows，推荐给最终用户）**

从 Releases 下载 `txt2md.exe`（单文件，免安装）。双击进图形界面，
或命令行调用：`txt2md.exe report.docx --to md`。

**pip 安装**

```bash
pip install txt2md          # 核心转换
pip install txt2md[gui]     # 带图形界面
pip install txt2md[pandoc]  # 附带 pandoc 兜底引擎（约 231 MB）
```

**源码运行**

```bash
git clone https://github.com/Xiaolinkemengwei/txt2md.git
cd txt2md
pip install -r requirements.txt
python txt2md.py --gui
```

### 3.2 图形界面操作

1. 点击「选择文件」/「选择文件夹」，或直接把文件拖进窗口
2. 在「目标格式」里点选目标格式（不可用的格式是灰的，鼠标悬停有原因）
3. 按需开关「智能排版」「覆盖同名文件」
4. 点「一键转换」（或 `Ctrl+Enter`）

转换日志会逐条显示结果：成功的显示输出路径，跳过的说明原因，失败的给出具体错误。

### 3.3 命令行

```bash
# 基础
txt2md note.txt                    # txt → md
txt2md report.docx --to txt        # Word → 纯文本
txt2md 数据.xlsx --to md            # Excel → Markdown 表格
txt2md 手册.md --to pdf             # Markdown → PDF

# 批量
txt2md ./docs --to pdf -o ./out    # 递归转 PDF，保留目录结构

# 决策辅助
txt2md --formats                   # 打印本机能力矩阵
txt2md --engines                   # 打印引擎探测结果
txt2md ./docs --to pdf --dry-run   # 只看会发生什么，不动手
```

### 3.4 参数完整表

| 参数 | 默认 | 说明 |
|---|---|---|
| `paths` | — | 文件或目录，可多个 |
| `-t, --to` | `md` | 目标格式；支持别名 `word` / `excel` / `markdown` |
| `-f, --from` | 自动 | 强制指定源格式，用于扩展名不规范的文件 |
| `-o, --out` | 源旁 | 输出目录 |
| `--force` / `--overwrite` | 关 | 覆盖已存在的目标 |
| `--plain` | 关 | 逐字保真，不加 Markdown 标记 |
| `--encoding` | 自动 | 强制源编码 |
| `--sheets` | 全部 | 只转指定工作表，逗号分隔 |
| `--dry-run` | 关 | 只预检 |
| `--no-verify` | 关 | 跳过产物校验 |
| `--formats` / `--engines` | — | 打印信息后退出 |
| `-q, --quiet` | 关 | 只输出汇总 |
| `-V, --version` | — | 版本号 |

退出码：`0` 全成功 / `1` 有失败 / `2` 参数或路径错误。

```

├─ core/                     # 转换内核（不含界面依赖）

│  ├─ model.py               #   统一文档模型 + 模型间转换（含结构表）
│  ├─ mdparse.py             #   GFM 块解析 + 行内标记降级
│  ├─ htmlio.py              #   HTML 解析与渲染（PDF 打印共用同一套 CSS）
│  ├─ readers.py             #   7 种格式 → Document
│  ├─ writers.py             #   Document → 7 种格式（原子写入）
│  ├─ registry.py            #   格式表、引擎探测、能力矩阵
│  ├─ pipeline.py            #   任务规划、防呆预检、执行、产物校验
│  ├─ legacy.py              #   1.0 排版算法（txt → md 直通）
│  ├─ pandoc_fallback.py     #   pandoc 兜底通道
│  └─ errors.py              #   分层异常
├─ gui/                      # Fluent Design 界面
│  ├─ app.py                 #   主窗口 + 转换线程
│  ├─ theme.py               #   设计令牌与全局 QSS
│  └─ widgets.py             #   自绘控件（卡片/开关/胶囊/日志行）
├─ tests/
│  ├─ test_convert.py        #   内核测试 87 项
│  ├─ test_gui_flow.py       #   界面测试 14 项
│  └─ shot_gui.py            #   多尺寸截图
├─ docs/                     # 项目介绍、2.0 设计大纲
├─ research/                 # 开源方案调研与实验脚本
├─ tools/                    # build.py / make_icon.py / enable_ci.py
├─ ci/                       # GitHub Actions 工作流（启用方式见 ci/README.md）
└─ txt2md.spec               # PyInstaller 打包配置
```

**分层纪律**：`core/` 不 import `gui/`。核心库可以独立用于脚本、CI、服务端，
界面只是它的一层薄壳。这条纪律保证核心逻辑的可测试性。

## 5. 配置说明

本项目没有配置文件——所有行为通过命令行参数或界面控件控制。这样做的理由是：
转换工具的使用是「一次性任务」而非「长期驻留服务」，引入配置文件只会增加心智负担。

### 5.1 编码策略

探测顺序（`core/readers.py::decode_bytes`）：

1. **BOM** —— 有 BOM 直接确定（UTF-8-SIG / UTF-16LE/BE / UTF-32LE/BE）
2. **严格 UTF-8** —— 能解就是 UTF-8，无需猜测
3. **用户指定** —— `--encoding` 优先
4. **中文编码候选打分** —— GB18030 / Big5 / Shift-JIS / EUC-KR 逐个试解，
   对结果按「常见汉字占比 − 控制字符与替换符占比」打分择优
5. **charset-normalizer** —— 对西文编码兜底
6. **容错解码** —— 全部失败则 `utf-8 replace`，并在结果中标注编码不可靠

第 4 步是关键。GBK 与 Big5 的高位区重叠，按顺序硬试会把繁体文件解成乱码；
打分择优能让两份候选竞争，选「更像正常中文」的那个。

### 5.2 智能排版规则

`txt → md` 默认启用（界面开关 / `--plain` 关闭）。

| 输入特征 | 输出 |
|---|---|
| 已是 Markdown 语法（`#` / `>` / 列表标记） | 原样保留 |
| 全大写英文短行（≤60 字符、无句点） | `## Title Case` |
| 首个非空段落 | `# 标题`，且只生效一次 |
| 其他 | 原样保留，不删改任何正文 |

这套规则来自 1.0，**2.0 原样保留**（`core/legacy.py`），并有字节级断言守着（第 8.2 节）。

### 5.3 保真策略

不同格式的能力边界不同，工具按「能保多少保多少」处理，并在 README 与界面里明示：

| 转换 | 保留 | 不保留 | 原因 |
|---|---|---|---|
| txt ⇄ md | 内容逐字节 / 智能排版 | — | 纯文本无结构损失 |
| md ⇄ txt | 全部文字、段落、列表、表格 | Markdown 标记 | txt 无标记概念 |
| md ⇄ xlsx | 标题级别、列表层级、代码语言 | 空行数量、列对齐 | Excel 无对应概念 |
| md ⇄ docx | 标题、粗斜体、嵌套列表、引用、代码块、表格 | 行内代码、代码语言、列对齐 | Word 无对应概念 |
| csv ⇄ xlsx | 每格内容、前导零、小数位精度 | — | 结构同构 |
| * → pdf | 全部内容与基础排版 | 原版式 | PDF 是渲染终点 |

### 5.4 环境变量

无。所有路径由参数决定，不读环境变量——避免「在我机器上好用」的问题。

## 6. 打包发布

### 6.1 产物

`python tools/build.py` 一条命令产出：

| 文件 | 说明 |
|---|---|
| `dist/txt2md.exe` | 单文件可执行程序，无控制台窗口，含图标与版本资源 |
| `dist/txt2md-<ver>-win64.zip` | 发布包：exe + README + LICENSE + 第三方声明 + CHANGELOG |
| `dist/txt2md-<ver>-py3-none-any.whl` | pip 安装包 |
| `dist/txt2md-<ver>.tar.gz` | 源码分发包 |
| `dist/SHA256SUMS.txt` | 校验和，供下载后核验 |

构建选项：

```bash
python tools/build.py              # 全部产物
python tools/build.py --no-wheel   # 跳过 wheel（只出 exe 与 zip）
python tools/build.py --onedir     # 目录版，启动更快但文件多
```

版本号唯一来源是 `txt2md.py` 的 `__version__`，构建时自动写入 exe 版本资源。

### 6.2 打包注意事项

- **`core/` 必须在 hiddenimports 里**：读取器/写出器是按需动态导入的，
  PyInstaller 静态分析看不到，漏了会在运行时才报 `ModuleNotFoundError`
- **pdfminer 需要数据文件**（CMap 等），必须 `collect_data_files`，否则中文 PDF 解析失败
- **pandoc 显式排除**：二进制约 231 MB，为边际收益把包体积放大数倍不划算

### 6.3 发布流程

```bash
# 1. 更新 __version__ 与 CHANGELOG
# 2. 本地验证
python tests/test_convert.py
python tests/test_gui_flow.py
python tools/build.py
dist\txt2md.exe                  # 双击确认能启动

# 3. 打标签发布
git tag v2.0.0
git push origin main --tags
gh release create v2.0.0 dist/*.zip dist/*.whl --title "v2.0.0" --notes-file docs/RELEASE_NOTES_v2.0.0.md
```

## 7. 架构设计

### 7.1 核心思路：一个模型，多个导出器

格式互转如果按「M 种源 × N 种目标」逐条实现，就是 42 条各自为政的代码路径，
每条都可能踩不同的坑。2.0 采用**统一文档模型 + 多导出器**：

```
        ┌──────┐  ┌──────┐  ┌──────┐        ┌──────┐  ┌──────┐  ┌──────┐
        │ txt  │  │  md  │  │ docx │  ...   │  md  │  │ docx │  │ pdf  │
        └──┬───┘  └──┬───┘  └──┬───┘        └──▲───┘  └──▲───┘  └──▲───┘
           │         │         │               │         │         │
           └─────────┴────┬────┘               │         │         │
                          ▼                    │         │         │
                   ┌─────────────┐             │         │         │
                   │  Document   │             │         │         │
                   │ TextDoc     │─────────────┴─────────┴─────────┘
                   │ Workbook    │
                   └─────────────┘
                    7 个读取器              7 个写出器
```

代价是模型必须足够表达力（要能装下标题层级、列表嵌套、表格、代码块），
收益是所有转换路径共享同一套语义，行为一致、可测。

这个模式参考了 [docling](https://github.com/docling-project/docling)（MIT）的
`DoclingDocument` 设计，但去掉了它的重型依赖（版面分析模型 / Torch）——
本项目的输入是办公文档而不是扫描件，不需要视觉模型。

### 7.2 两种载荷

`Document` 有两个载荷，按格式类别选用：

- **`TextDoc`**：块序列。承载 txt / md / html / docx / pdf
- **`Workbook`**：多工作表二维矩阵。承载 csv / xlsx

分两种而不是合成一种，因为 xlsx 的「多 sheet」维度塞进块序列会丢失。
两者之间有受控的转换通道（`as_text()` / `as_book()`），转换规则显式且可测。

`TextDoc` 的块类型：

| 块 | 承载 | 关键字段 |
|---|---|---|
| `heading` | 标题 | `level` 1-6 |
| `paragraph` | 段落 | `text` |
| `list` | 列表 | `items` / `ordered` / `level` / `start` |
| `code` | 代码块 | `text` / `lang` |
| `quote` | 引用 | `text` |
| `table` | 表格 | `rows` / `header` / `align` |
| `divider` | 分隔线 | — |
| `raw` | 未解析原文 | `text`，逐字保留 |

`raw` 是保真的最后一道防线：解析器看不懂的内容原样塞进 `raw` 块，
写出时原样吐出，**绝不因为「不认识」而丢弃**。

### 7.3 为什么不让 pandoc 当主引擎

调研阶段实测过 pandoc 3.9，它在三个方面不适合当主路径：

| 事实 | 影响 |
|---|---|
| `pandoc.exe` 有 231 MB | 安装包体积放大数倍，而内置实现已覆盖全部 7 种格式 |
| xlsx **只能读不能写** | 7 种格式里缺一角，仍需自己实现 xlsx 写出 |
| PDF 输出依赖外部 LaTeX | 用户大概率没装，实测直接报 `pdflatex not found` |
| xlsx 读取对生成器敏感 | openpyxl 存的表报 `Entry not found`，xlsxwriter 存的正常 |

因此策略是：**内置实现为主，pandoc 仅作兜底**。内置失败时若机器上有 pandoc 就再试一次，
并把「改用 pandoc 完成」写进结果提示，不静默切换。

### 7.4 PDF 生成链路

PDF 是唯一需要外部程序的格式，但不需要额外安装：

```
TextDoc → render_html()（含 @page 与分页规则的打印版 CSS）
        → 临时 HTML 文件
        → msedge/chrome --headless --print-to-pdf
        → 校验 %PDF 魔数 → 原子写入
```

用浏览器而不是 reportlab/fpdf2 的原因：后两者需要手工嵌入中文字体，
且不处理分页断行，版式质量差一个量级。Windows 上 Edge 是系统组件，命中率极高。

**不信任进程退出码**：浏览器经常返回 0 却没真正写文件，所以输出后必须校验魔数与大小。

### 7.5 线程模型

GUI 的转换在 `QThread` 里跑，主线程只负责界面更新。逐条信号回传（`item_ready`），
所以长任务期间进度条与日志是实时更新的，窗口不会假死。

单个任务失败只记录不中断——批量转换最怕「一个坏文件让后面全不跑」。

## 8. 测试

### 8.1 测试设计原则

不测「能跑通」，测「结果对不对」：

- 往返转换后比对**块结构**而不是文件大小
- 保真断言用具体 token（`"# 项目标题"`、`"嵌套项"`）而不是非空判断
- 防呆用例验证「拒绝之后原件是否完好」而不只是「是否报错」

### 8.2 内核测试（87 项）

`python tests/test_convert.py`

| 组 | 项数 | 关键断言 |
|---|---|---|
| 编码探测 | 9 | GBK / Big5 简繁不混淆、BOM 处理、二进制识别 |
| Markdown 行内降级 | 9 | 紧贴中文的 `**粗体**` 能剥离、`2 * 3` 不误伤 |
| Markdown 解析 / 写出 | 9 | 块类型序列、嵌套层级、渲染幂等、结构等价 |
| 1.0 兼容 | 6 | 管线产物与 1.0 算法**字节级一致** |
| 跨格式保真 | 30 | csv⇄xlsx 前导零与小数位、md→xlsx→md 结构还原、md→pdf→md 不重复、`--plain` 逐字 |
| 防呆 | 16 | 自毁拦截、跳过不覆盖、损坏文件不留残骸 |
| 全矩阵 | 2 | **42 个格式组合无崩溃**、成功产物非空 |
| 产物校验 | 3 | 空产物 / 伪 PDF 被拦截 |
| 命令行输出兼容 | 3 | GBK 终端下 `--formats` / `--engines` / `--version` 不崩溃 |

### 8.3 界面测试（14 项）

覆盖扫描统计、格式切换、目标格式智能建议、转换流程产出、重复转换跳过。
模态对话框在离屏平台会永久阻塞，测试里统一短路。

## 9. 已知限制

诚实列出，避免用户踩坑后再来提 issue：

| 限制 | 说明 | 规避 |
|---|---|---|
| 扫描版 PDF 不可读 | 无文本层，需 OCR，本工具不做 | 先用 OCR 工具处理 |
| PDF 输出是文本重排 | 不是原版式复刻 | 需版式请用 Word/LaTeX 导出 |
| docx 丢版式细节 | 分栏、页眉页脚、脚注、批注、图片不保留 | — |
| xlsx 中转丢列对齐 | Excel 无 Markdown 表格对齐概念 | 走 md → md 直转 |
| 不支持 `.doc` / `.ppt` | 旧二进制格式与演示文稿 | 先在 Office 里另存为新格式 |
| 不支持 `.epub` / `.odt` | 未纳入格式矩阵 | 装 pandoc 后可走兜底 |
| 简繁识别非 100% | 极短的 Big5 片段可能误判 | `--encoding big5` 显式指定 |

## 12. 路线图

已明确的候选（按优先级）：

1. **`.doc` / `.odt` / `.epub` 支持**：通过 pandoc 兜底通道扩展，不需要改架构
2. **图片提取**：docx/xlsx 内嵌图片导出到附件目录，Markdown 里引用相对路径
3. **深色主题**：Fluent 深色令牌已有设计，待补齐
4. **PDF 版式保真**：接入 LibreOffice headless（需用户安装），`docx → pdf` 走版式转换
5. **右键菜单集成**：Windows 资源管理器「转换为 Markdown」
