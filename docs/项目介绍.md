# txt2md 项目介绍

> TXT 一键转 Markdown —— 面向中文 Windows 用户的批量转换工具，带 Fluent Design 桌面界面。

---

## 1. 项目简介

`txt2md` 解决一个具体而琐碎的问题：**手里有一堆 `.txt` 笔记，想批量变成 `.md` 丢进 Obsidian / Typora / GitHub，但复制粘贴太慢，写脚本又要处理 GBK 乱码。**

它把这件事压缩成两步：选文件或文件夹 → 点「一键转换」。转换在本地完成，不联网、不上传、不改动原文件（只新增 `.md`）。

项目有两个入口，共用同一套转换逻辑：

| 入口 | 依赖 | 适合谁 |
|---|---|---|
| 图形界面（Fluent Design） | PySide6 | 不想碰命令行的用户；需要逐条查看转换结果 |
| 命令行 | **纯标准库，零依赖** | 脚本/批量/CI 场景；服务器或极简环境 |

**设计立场**

- **内容安全优先**：智能排版只做「加标题、识别列表」，绝不删改正文；拿不准的规则宁可不加。
- **中文优先**：编码探测、无空格文本的行宽判断、中文标点处理都按中文语料设计，而不是把英文规则直接搬过来。
- **不重复造轮子，但要挑对轮子**：智能排版思路借鉴成熟开源实现，同时修掉它与中文语料冲突的部分（见 `research/2026-11-07-txt2md-开源调研.md`）。

**适用人群**：个人笔记迁移、技术文档整理、教学资料归档、需要把导出文本转成 Markdown 的工作流。

## 2. 功能特性

### 转换能力

| 特性 | 说明 |
|---|---|
| 批量转换 | 支持多选文件、整目录递归（含子目录），一次处理成百上千个文件 |
| 编码自动识别 | `BOM → UTF-8 → Big5 → GBK` 依次探测；记事本默认的 GBK 文件不再报错，输出统一 UTF-8 |
| 智能排版 | 首行作为 `# 标题`、识别已有 `#`/`>`/列表/分隔线、全大写英文短行作 `## 标题` |
| 纯转换模式 | `--plain`：内容一字不动，仅改扩展名 |
| 覆盖策略 | 默认跳过已存在的 `.md`，显式 `--overwrite` 才覆盖，避免误伤 |
| 失败隔离 | 单个文件出错不影响整体任务，逐条记录原因 |
| 末尾规范化 | 两种模式都保证文件以单个换行结束（Markdown 规范） |

### 界面特性

| 特性 | 说明 |
|---|---|
| Fluent Design | Fluent 2 亮色设计系统：白色圆角卡片、柔和投影层级、`#0F6CBD` 强调色 |
| 字体规范 | 运行时探测 Segoe UI Variable Text → Segoe UI → 微软雅黑；图标用 Segoe Fluent Icons |
| 自绘控件 | Fluent 开关（120ms 缓动）、状态胶囊、细滚动条、省略文本、渐变图标块 |
| 实时反馈 | 选中即显示「找到 N 个 .txt 文件」、逐条日志、进度条、成功/跳过/失败汇总 |
| 响应式 | 全弹性布局，最小 720×660 至 4K 均不破版；Qt 自动处理高 DPI 缩放 |
| 快捷操作 | 拖拽文件进窗口、`Ctrl+Enter` 转换、`清空` 重置日志 |

## 3. 安装与使用

### 方式一：下载打包版（推荐给普通用户）

1. 打开 Releases 页面，下载 `txt2md-1.0.0-win64.zip`。
2. 解压到任意目录（无需安装，不写注册表）。
3. 双击 `txt2md.exe` 即可使用。

> 首次运行 Windows 可能弹出 SmartScreen 提示（未签名的开源程序常见现象），
> 选择「更多信息 → 仍要运行」即可。程序不联网，可用防火墙或抓包自行验证。

### 方式二：pip 安装（Python 用户）

```bash
# 仅命令行（零第三方依赖）
pip install txt2md

# 含图形界面
pip install "txt2md[gui]"
```

安装后可直接使用 `txt2md` 命令：

```bash
txt2md --version
txt2md ./notes -o ./out
```

### 方式三：从源码运行

```bash
git clone https://github.com/your-name/txt2md.git
cd txt2md

# 命令行：无需安装任何依赖
python txt2md.py notes.txt

# 图形界面：先装 PySide6
python -m pip install -r requirements.txt
python txt2md.py --gui
```

Windows 用户也可以双击 `启动GUI.bat`：脚本会检测缺失的依赖并自动安装，然后用无控制台方式启动界面。

### 命令行用法

```bash
# 单个文件：输出到源文件旁边
python txt2md.py note.txt

# 多个文件
python txt2md.py a.txt b.txt c.txt

# 整目录递归，输出到 out/ 并保留子目录结构
python txt2md.py ./notes -o ./out

# 纯转换：内容原样保留
python txt2md.py ./notes --plain

# 覆盖同名 .md
python txt2md.py ./notes --overwrite

# 查看版本
python txt2md.py --version
```

输出示例：

```
✓ notes\读书笔记.txt
    -> notes\读书笔记.md
- notes\会议纪要.txt
    -> notes\会议纪要.md
✗ notes\locked.txt
    原因: [Errno 13] Permission denied

汇总: 成功 1 / 跳过 1 / 失败 1
```

退出码：全部成功或有跳过为 `0`，存在失败为 `1`（便于脚本判断）。

### 图形界面操作步骤

1. **选择来源**：点「选择文件」（可多选）或「选择文件夹」，也可以把文件直接拖进窗口、或粘贴路径后回车。
2. **确认数量**：右上角实时显示「找到 N 个 .txt 文件」，未找到会变红提示。
3. **设置选项**：`智能排版`（默认开）、`覆盖已存在的 .md`（默认关）。
4. **一键转换**（或 `Ctrl+Enter`）：进度条推进，日志逐条显示 `完成 / 跳过 / 失败`，右侧显示目标文件名或失败原因。
5. **查看结果**：`.md` 生成在各自源文件旁边，汇总行显示成功/跳过/失败数量。

## 5. 配置说明

项目没有配置文件，所有行为由命令行参数或界面开关决定，**默认值即推荐值**。

### 命令行参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `paths` | 位置参数（可多个） | 无 | `.txt` 文件或目录；目录会递归收集 |
| `-o, --out DIR` | 路径 | 源文件所在目录 | 输出目录；批量时保留相对子目录结构 |
| `--smart` | 开关 | 开 | 智能排版（命令行默认开启，无需显式指定） |
| `--plain` | 开关 | 关 | 纯转换，内容原样保留，仅改扩展名 |
| `--overwrite` | 开关 | 关 | 覆盖已存在的 `.md`；关闭时同名文件跳过 |
| `--gui` | 开关 | 关 | 启动图形界面；无参数运行时同样进入界面 |
| `-V, --version` | 开关 | — | 打印版本号并退出 |

### 界面选项

| 选项 | 默认 | 对应命令行 |
|---|---|---|
| 智能排版 | 开启 | `--smart` |
| 覆盖已存在的 .md | 关闭 | `--overwrite` |

### 智能排版规则（按顺序匹配，命中即停）

1. 空行 → 保留空行（用于分隔段落）。
2. 已是 Markdown 语法（`#` 标题、`>` 引用、`-`/`*`/`+`/`1.` 列表、`---` 分隔线）→ **原样保留**。
3. 全大写英文短行（≤60 字符、无句点、含字母）→ `## Title Case`。
4. 文件首个非空文本行 → `# 该行内容`（只生效一次）。
5. 其他行 → 原样输出。

**刻意不做的事**：不按行宽折行、不自动加粗、不猜测代码块、不因「空格少」判定为代码。
原因：中文文本没有词间空格，任何依赖空格数量的规则都会误伤正文（详见调研文档）。

### 编码策略

| 顺序 | 编码 | 触发条件 |
|---|---|---|
| 1 | UTF-8 BOM / UTF-16 BOM | 文件头匹配 |
| 2 | UTF-8 | 可无异常解码 |
| 3 | Big5 | 可无异常解码 |
| 4 | GBK | 可无异常解码 |
| 5 | UTF-8 + 替换字符 | 兜底，保证不崩溃 |

输出**始终为 UTF-8（无 BOM）**，换行统一为 `\n`。

## 6. 打包发布

### 环境要求

- Windows 10 1809+ / Windows 11（x64）
- Python 3.9+
- 构建依赖：`pip install -r requirements.txt pyinstaller`

### 一键构建

```bash
python tools/build.py --clean
```

产物在 `dist/`：

| 文件 | 体积 | 说明 |
|---|---|---|
| `txt2md.exe` | 35.8 MB | 单文件可执行程序（GUI，无控制台窗口，含图标与版本资源） |
| `txt2md-1.0.0-win64.zip` | 35.6 MB | 发布包：exe + README + LICENSE + 第三方声明 + CHANGELOG |
| `txt2md-1.0.0-py3-none-any.whl` | 19 KB | Python 安装包（`pip install`，含 `txt2md` 命令入口） |
| `txt2md-1.0.0.tar.gz` | 21 KB | 源码分发包 |

验收入手点（已在本地实测通过）：

- 双击 exe 能打开界面，标题栏与任务栏显示自定义图标；
- 文件属性中可见 `文件版本 1.0.0`、`产品名称 txt2md`、`版权 MIT License`；
- `pip install dist/*.whl` 后 `txt2md --version` 输出 `txt2md 1.0.0`；
- zip 内除 exe 外还包含四份文档，解压即读。

wheel 与 sdist 由标准构建工具生成（`python -m build --no-isolation --sdist --wheel -o dist`），
`tools/build.py` 默认也调用 `pip wheel` 产出 wheel。

> `dist/` 与 `build/` 已在 `.gitignore` 中排除：二进制产物不进 Git 仓库，
> 通过 GitHub Releases 分发，避免仓库体积膨胀。仓库只保留源码与构建脚本。

### 构建选项

```bash
python tools/build.py --no-wheel   # 只出 exe 和 zip
python tools/build.py --onedir     # 目录版（启动更快，便于替换 Qt 库）
```

目录版用 `TXT2MD_ONEFILE=0` 传给 `txt2md.spec`，产出 `dist/txt2md/` 文件夹。

### 打包实现要点

- **版本号单一来源**：`txt2md.py` 的 `__version__`，`txt2md.spec` 在构建时读取，
  同时写入 Windows 版本资源（文件属性中可见）与发布包文件名。
- **体积控制**：`txt2md.spec` 排除 `tkinter`、`unittest`、`setuptools` 及未使用的 Qt 模块
  （Qml/Quick/WebEngine/Multimedia/Sql/Charts 等）。
- **图标**：`tools/make_icon.py` 用 Qt 渲染 16/24/32/48/64/128/256 七个尺寸，
  组装成 PNG 压缩的 ICO（Vista+ 原生支持）。
- **无控制台窗口**：`console=False`；因此打包版只提供 GUI，命令行请用源码或 pip 安装。

### 发布流程建议

```bash
# 1. 更新 txt2md.py 的 __version__ 与 CHANGELOG.md
# 2. 本地验证
python tests/test_gui_flow.py
python tools/build.py --clean
dist\txt2md.exe            # 双击确认能启动

# 3. 打标签并发布
git tag v1.0.0
git push origin v1.0.0
gh release create v1.0.0 dist/*.zip dist/*.whl --title "v1.0.0" --notes-file CHANGELOG.md
```

## 7. 架构设计

### 数据流

```
用户输入（界面/命令行）
        │
        ▼
  collect_txt_files()        路径 → 待转换文件列表
        │
        ▼
  read_text_smart()          BOM/UTF-8/Big5/GBK 探测解码
        │
        ▼
  to_markdown(smart)         规范换行 → 逐行启发式 → 末尾规范
        │
        ▼
  convert_file()             跳过/覆盖判定 → 写 UTF-8
        │
        ▼
  结果（命令行走 stdout；界面走 Qt 信号）
```

### 线程模型

界面把转换放进 `QThread`（`ConvertWorker`）：

- 每完成一个文件发 `item_ready(kind, src, dst, reason)`，主线程即时渲染一行日志；
- 全部结束发 `finished_all(ok, skipped, error, total)`，刷新汇总与进度条；
- 转换期间禁用按钮，避免重复触发；单文件异常在 worker 内捕获，不影响后续任务。

这样即使一次处理上千个文件，界面也不会「未响应」。

### 技术选型

| 决策 | 选择 | 原因 |
|---|---|---|
| 界面框架 | PySide6（Qt 6） | 真实投影/圆角/高 DPI；原生文件对话框；跨平台可扩展 |
| 未用 tkinter | — | 无法做真实阴影与圆角，Fluent 观感只能靠 Canvas 硬画；且部分精简版 Python 缺该模块 |
| 未用 Web UI | — | 需要额外进程与端口，与「本地小工具」形态不符 |
| 样式集中 | `theme.py` + QSS | 配色/圆角/字号单点维护，避免控件内散落硬编码色值 |
| 自绘控件 | `widgets.py` | Qt 无内置开关/胶囊/阴影卡片，自绘可精确对齐 Fluent 规范 |
| 命令行零依赖 | 纯标准库 | 服务器/CI 场景直接可用；也是 LGPL 的规避路径 |

### Fluent 设计令牌（摘要）

| 令牌 | 值 | 用途 |
|---|---|---|
| 底层背景 | `#F3F3F3` | 窗口底 |
| 卡片 | `#FFFFFF` + `#E5E5E5` 描边 | 内容容器，8px 圆角 |
| 投影 | 模糊 20px、偏移 (0,5)、alpha 85 | 卡片层级 |
| 强调色 | `#0F6CBD` / hover `#115EA3` / pressed `#0F548C` | 主按钮、开关、聚焦态 |
| 强调浅底 | `#EBF3FC` | 幽灵按钮 hover、图标块 |
| 文本 | `#1B1B1B` / `#616161` / `#8A8A8A` | 主/次/三级信息 |
| 状态色 | 成功 `#0F7B0F` / 警告 `#9D5D00` / 危险 `#C42B1C` | 日志胶囊与汇总 |

## 8. 测试

```bash
# 1. 命令行转换回归（3 个样例，覆盖 GBK / 已有标记 / 大写标题）
python txt2md.py tests/sample -o tests/out --overwrite

# 2. 界面层功能测试（扫描统计、转换线程、跳过逻辑）
python tests/test_gui_flow.py

# 3. 视觉回归（生成 720/1000/1120/860 宽多尺寸截图）
python tests/shot_gui.py
```

**覆盖范围**

| 用例 | 验证点 |
|---|---|
| GBK 中文文件 | 解码正确、首行成标题、列表原样 |
| UTF-8 + 已有 Markdown | 已有语法不被二次加工、普通段落不被误判为标题 |
| 全大写英文短行 | 转 `## Title`，且不抢占「首个标题」名额 |
| `-o` 输出目录 | 批量保留相对结构、单文件落到指定目录 |
| 已存在 `.md` | 默认跳过、`--overwrite` 才覆盖 |
| 界面转换线程 | 3 个文件全部生成 `.md`，统计正确；重复执行全部跳过 |

**已知测试盲区**：GUI 的人工交互（拖拽、快捷键）未自动化；Big5 语料未实测；
打包后 exe 只做了启动验证，未做长时间压力测试。

## 9. 已知限制

1. **仅亮色主题**：为保证跨设备视觉一致，界面固定 Fluent 亮色；未跟随系统深色模式。
2. **打包仅 Windows**：`txt2md.spec` 面向 Windows；macOS/Linux 需从源码运行
   （PySide6 本身跨平台，`gui/` 未使用 Windows 专有 API）。
3. **只处理 `.txt`**：`.text`、`.log` 等扩展名暂不支持（可先用 `--plain` 改扩展名后处理）。
4. **不做格式推断**：不识别表格、图片、脚注；输出是「带标题的纯文本」，不是全自动排版。
5. **大文件策略**：整体读入内存；单文件数百 MB 的极端场景未优化。

## 11. 贡献指南

完整流程见 [CONTRIBUTING.md](CONTRIBUTING.md)，核心几条：

1. **环境**：`pip install -r requirements.txt`；只改命令行则无需任何依赖。
2. **提交前自检**：命令行回归 + `tests/test_gui_flow.py` + `tests/shot_gui.py` 三条命令全绿。
3. **代码约定**：注释与文案用中文、标识符用英文；PEP 8；行宽 ≤ 100。
4. **分层纪律**：转换规则只能写在 `txt2md.py`；`gui/` 不得实现业务逻辑。
5. **样式纪律**：颜色/圆角/字号一律走 `gui/theme.py`，禁止控件内硬编码色值。
6. **提交信息**：Conventional Commits（`feat:` / `fix:` / `docs:` / `test:` / `chore:`）。
7. **界面改动**：附 `tests/preview/` 下的最新截图对比。
8. **变更记录**：行为变化写入 `CHANGELOG.md` 的 Unreleased 段。

**特别提醒**：新增「智能排版」规则时，务必用中文样例验证——中文没有词间空格，
任何基于空格数量的启发式都会误伤正文。
