# AI eye 2.2 方案：图表还原 + 图片识别

> 状态：**已实现**（2026-11-07 交付 2.2.0）　|　基线版本：2.1.0 → 2.2.0
>
> 落地时的三处决策：表格本期只裁图不重建；图片 OCR 保留原图 + 文字；
> 结果查看用独立窗口（双击记录打开，「在文件夹中显示」移到右键）。
> 实测结论见文末「八、落地结果」。

## 一、问题定位（已用真实样本复现）

样本：某出版的 275 页扫描版 PDF（每页为**整页位图**，无文字层）。

对第 41 页跑现有 `--ocr` 路径，OCR 返回 27 行，其中 8 行是图内元素：

```
3.60 / 3.00 / 2.80 / 2.40 / 2.26      ← K 线图纵轴刻度
11.59 / 11.00 / 13.50 / 13.88 / 3.5   ← 第二张图的纵轴刻度
放量                                    ← 图内标注气泡
```

这些行被 `_blocks_from_lines` 当成正文，于是成段数字堆在「图 2-13 上升旗形图例」前后——这就是用户看到的"乱码"。

第 61 页更严重：43 行 OCR 结果里 **25 行**在图区内（`低位孕线`、`前浪顶部`、`48000`、`80300`…）。

**根因**：`read_pdf_file` 的 OCR 分支只做「整页文字识别」，没有版面概念，不区分「正文」与「图内元素」。

## 二、技术选型：为什么自研而不是引第三方

用户要求「寻找或编写一个画线工具」。候选评估：

| 方案 | 能力 | 许可 | 体积代价 | 结论 |
|---|---|---|---|---|
| docling | 版面+表格+阅读顺序 | MIT | torch + 模型 ≈ 1.5 GB | 与 188 MB 单文件 exe 冲突 |
| layoutparser | 版面检测 | Apache-2.0 | torch 或 TF ≈ 800 MB | 同上 |
| DocLayout-YOLO (ONNX) | 版面检测 | AGPL-3.0 | 模型 25–40 MB | 许可与 MIT 项目冲突，可作后续可选增强 |
| img2table | 只做表格 | GPL-3.0 | 中等 | 不解决插图，许可冲突 |
| **自研（OpenCV 形态学 + 现有 OCR 框）** | 插图/表格区分 + 裁切 | 本项目 | **0 新增依赖** | **采用** |

关键前提：OCR 已经产出**每个文字行的四点框**，这本身就是一份免费的文字掩膜。把掩膜从页面暗像素里减掉，剩下的连通结构就是图。

### 算法验证（已在真实页面上跑通）

```
p41  图区 2 个：(117,126)-(782,450)   (146,777)-(786,1103)   ← 两张 K 线图，与版面吻合
p21  图区 2 个，框住 13/31 行图内文字
p61  图区 3 个，框住 25/43 行图内文字
p9   图区 0 个（该页是双栏目录，纯文字）← 零误检
```

单页额外开销约 0.1 秒（OCR 本身 2.8–4.6 秒），可忽略。

## 三、需求 1：图表还原

### 3.1 新建 `core/layout.py`

```python
@dataclass
class Region:
    kind: Literal["figure", "table"]
    bbox: tuple[int, int, int, int]     # x0, y0, x1, y1（像素）
    caption: str = ""
    index: int = 0                       # 页内序号，用于命名 p041_fig1.png

def detect_regions(gray: np.ndarray, lines: list[dict]) -> list[Region]
```

四步：

1. **文字掩膜**：OCR 行框外扩 2px 涂白，得到「只剩图形」的残差图
2. **连块**：残差图做闭运算（核 41×21，横向更宽——K 线柱体横向密集），取连通域
3. **过滤**：宽 ≥ 页宽 30%、高 ≥ 页高 10%、面积 ≥ 1%；低于此的视为装饰线
4. **表/图判别**：区域内提取长横线与长竖线（形态学开运算，横核 1×40、竖核 40×1），若竖线 ≥ 2 且横线 ≥ 3 → `table`，否则 `figure`

**边界收紧**：闭运算会让框外扩约 20px，裁切前按残差图的实际包围盒内缩，避免把图注吃进图里。

### 3.2 图注归属

图区下方 ≤ 48px、以 `图` / `Figure` / `图 2-13` 开头、字号与正文同级的行 → 判为图注：

- 从正文行列表中移除（避免重复）
- 挂到 `Region.caption`
- 写出到 md 时同时作为 `alt` 文本和下方题注

### 3.3 模型扩展（`core/model.py`）

```python
BlockKind += "image"

@dataclass
class ImageRef:
    name: str          # p041_fig1.png，目标目录内的文件名
    path: Path         # 临时文件路径，写出时复制/嵌入
    alt: str = ""      # 图注文本
    width: int = 0
    height: int = 0

Block.image: ImageRef | None = None
Document.assets: list[ImageRef] = field(default_factory=list)
```

图片先落**临时目录**（`tempfile.mkdtemp()`），`pipeline.convert_one` 在 `finally` 里清理——避免 400 张图全驻留内存（实测约 60 MB，但整本书可能更高）。

### 3.4 各格式写出行为

| 目标 | 图块处理 |
|---|---|
| md | 图片落盘到 `<目标名>_assets/`，写 `![图 2-13 上升旗形图例](目标名_assets/p041_fig1.png)` |
| html | `<figure><img src="..." alt="..."><figcaption>...</figcaption></figure>`，同级目录 |
| docx | `add_picture(width=Cm(15))` + 居中题注段落 |
| pdf | 走 HTML 打印通道，图片以 `file://` 引用临时目录 |
| txt | 保留占位 `【图】图 2-13 上升旗形图例`——不丢信息，也不塞二进制 |
| xlsx | 题注写入单元格；图片以 `openpyxl.drawing.image` 锚定（`--no-images` 可关） |
| csv | 只留题注行 + `warning: 图片未导出` |

### 3.5 失败与降级

- **整页图**（封面、整版图录）：检出单框覆盖 > 85% 页面 → 整页裁图，不再剔除文字
- **密集标注图**（OCR 框吃掉大部分暗像素，残差过少）→ 退回「行密度法」：正文行行距稳定、左边界一致；图区行距无规律 → 二次判定
- **检测不到但仍像图**：不剔除任何文字，行为与 2.1.0 一致（不劣化）

## 四、需求 2：图片识别

### 4.1 格式矩阵

`core/registry.py`：

```python
Format.role: Literal["source", "sink", "both"] = "both"

"image": Format("image", "图片（OCR）",
                (".png", ".jpg", ".jpeg", ".webp", ".bmp", ".tif", ".tiff"),
                kind="text", role="source")
```

- `validate_target()` 拒绝把图片作为**输出**格式（`图片 只能作为源格式`）
- CLI `--to image` 直接报错并列出可选目标
- GUI 格式卡片不出现「图片」——它是输入，不是输出

### 4.2 读取器 `read_image_file`

1. 小于 1500px 宽先等比放大（小图 OCR 精度差）
2. 与 PDF 共用同一条链：`ocr_page_lines` → `detect_regions` → 剔除图内行 → `_blocks_from_lines`
3. 单图即整篇文档；图片本身作为第一个 `image` 块（导出 docx/md 时可保留原图）
4. 多图批量（选中多个 png）按文件各自成篇，与现有批量逻辑一致

### 4.3 界面：结果查看与复制

新增 `gui/viewer.py` —— **非模态结果查看器**（`QDialog`，1200×800）：

```
┌─ 识别结果 · 报表.png ────────────────────────┐
│ [Markdown] [纯文本]        3 图 · 1,284 字   │
│ ┌──────────────────────────┐ ┌────────────┐ │
│ │ # 报表标题               │ │            │ │
│ │                          │ │  原图缩略  │ │
│ │ 第一段识别文本…          │ │            │ │
│ │                          │ │            │ │
│ └──────────────────────────┘ └────────────┘ │
│ [复制全部] [复制选中] [打开文件] [另存为…]  │
└─────────────────────────────────────────────┘
```

- 文本来自 `Result.preview_text`（转换时顺带缓存，**不重新读盘**；截断 2 MB 防内存爆）
- 「另存为…」复用 `write_any`，可直接导出为 7 种格式中的任意一种
- 记录行：双击 → 打开查看器（原「双击打开输出位置」改为右键菜单项）

### 4.4 OCR 开关语义调整

- 输入含**图片** → OCR 强制开启，开关置灰并提示「图片必须经过文字识别」
- 输入含**扫描版 PDF** → 保持现状（用户可选）
- 输入为正常文档 → 开关置灰

真实样本（上述 275 页扫描版，抽第 21 / 41 / 61 页）：

- 6 张图全部检出并裁出，题注全部正确（`图1-16敦煌种业实战图谱` 等）
- 图内 114 行刻度与标注未进入正文，`3.60 / 2.80 / 48000` 零残留
- 纯文字页（第 9 页目录）零误检
- 单页总耗时 5.2 s（OCR 主体），版面分析 22 ms

### 过程中顺手修掉的两个老问题

1. **长句被误判为标题**：OCR 的字号是外接框高度，行内有括号/数字时框会被撑高，
   「如图2-14所示，是美尔雅（600107）的日K线走势图…」整行变成 h3。
   现在 OCR 路径要求「长句不得含句中标点」才算标题。
2. **中文段首缩进被当成列表**：正文段首缩进两字符与列表缩进在几何上同构，
   一本书几乎每段首行都被判成列表项。扫描件路径改为只认显式项目符号。
