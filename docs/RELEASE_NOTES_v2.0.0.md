从「TXT 转 Markdown」变成「文档格式互转」。7 种格式两两互通，42 个方向都能走，核心转换不依赖任何外部程序。

## 下载

| 选项 | 适合谁 |
|---|---|
| **`txt2md-2.0.0-win64.zip`** | Windows 用户，解压双击 `txt2md.exe` 即可，**不需要安装 Python** |
| `txt2md-2.0.0-py3-none-any.whl` | 已有 Python 环境，`pip install` 后可用 `txt2md` 命令 |
| `txt2md-2.0.0.tar.gz` | 想读源码或二次开发 |

```powershell

```

## 这个版本做了什么

**7 种格式任意互转**：txt / md / html / csv / xlsx / docx / pdf。选一个源格式、一个目标格式，
剩下的交给它。命令行同样：

```bash
txt2md note.txt                    # txt → md（和 1.0 一样）
txt2md report.docx --to txt        # Word → 纯文本
txt2md data.xlsx --to md           # 表格 → Markdown 表格
txt2md ./docs --to pdf -o ./out    # 整个目录转 PDF
txt2md --formats                   # 看本机能走哪些方向
```

**不是 42 条各写一遍的转换路径**。所有格式先读成统一的「块序列 / 工作表」中间模型，
再由 7 个写出器渲染。读是 7 份，写是 7 份，组合出 42 个方向——这才保证了
「md→docx」和「md→pdf」对同一份文档的理解是一致的。

**PDF 不需要装 Office 或 LaTeX**。走 HTML 中转 + 系统自带 Edge 的无头打印，
Windows 上开箱即用。

**防呆是这一版的重点**：

- 目标路径和源文件是同一个文件 → 直接拒绝，不会把自己的文件覆盖成空
- 目标已存在 → 默认跳过，要覆盖得显式加 `--force`
- 伪装的二进制文件（改了扩展名的图片）→ 识别出来并拒绝解码
- 写文件用「临时文件 + 原子替换」→ 中途失败不会留下半个损坏的文件
- 转换后自动校验产物：空的、假 PDF、坏 zip 一律算失败而不是"成功"
- `--dry-run` 先只列计划，不碰任何文件
- 本机缺依赖的方向直接在矩阵里标为不可用，GUI 里置灰并写明原因，不会让你点了才失败

## 保真：哪些保留，哪些不保留

这一版的目标是「尽量不丢数据」，不是「无损」。下面这些是实测过的边界：

| 内容 | 跨格式转换后 |
|---|---|
| 纯文字内容 | 全部保留 |
| 标题层级 | 保留 |
| 列表与嵌套层级 | 保留 |
| 代码块与语言标记 | 保留（txt 除外，纯文本无法承载） |
| 表格 | 保留（txt 除外） |
| 粗体 / 斜体 | docx / html 之间保留，转纯文本时剥离标记、保留文字 |
| 分隔线、引用块 | 保留 |
| 图片 | **不保留**（只在 docx 内原样留存，导出到其他格式时丢弃） |
| 字体、字号、颜色 | **不保留** |
| 页眉页脚、脚注、分栏 | **不保留** |
| PDF 的版式 | **不保留**，只取文本层重新排版 |
| xlsx 的公式、图表、条件格式 | **不保留**，只取单元格的值 |

另外两个精度细节：`12.50` 转一圈回来还是 `12.50`（按数字格式还原小数位，不会变成 `12.5`），
`007` 这样的前导零保持文本形式不被吃掉。

## 从 1.0 升级

不用担心旧脚本坏掉：

- `txt2md note.txt` 仍然输出 `note.md`
- `--plain` 仍然是逐字保真
- 1.0 的排版算法原样保留，txt → md 的输出与 1.0 **字节级一致**
- `convert_file` / `run_convert` / `read_text_smart` / `to_markdown` 等 API 保持可用

唯一的变化：依赖不再是零。xlsx / docx / pdf 分别需要 openpyxl / python-docx / pdfplumber，
缺哪个只少一种格式，其它照常。

## 已知限制

- 界面只有亮色主题，未跟随系统深色模式
- 仅提供 Windows 打包产物；macOS / Linux 需从源码运行
- PDF 输出依赖系统里的 Edge / Chrome；没有浏览器时该方向自动关闭
- PDF 读出的是文本层，扫描件（没有文本层的图片 PDF）读不出内容
- 打包后的 exe 体积从 1.0 的 36 MB 增长到约 119 MB，因为打包了表格、Word、PDF 的解析库
