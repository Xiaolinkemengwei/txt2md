# AI eye 2.3.0 发布说明

**发布日期**：2026-11-08  
**重点**：EPUB 双向支持 · 转换进度可见 · AI eye 导读 · 白天/黑夜主题

---

## 这一版加了什么

四个方向，互不干扰：

1. **EPUB**：电子书能读进来，也能把文档做成电子书
2. **进度**：不再是「点了按钮等黑箱」，单文件内部也在动
3. **AI eye 导读**：给 AI 一份文档地图，比把整本书塞进上下文更省
4. **深色主题**：一个按钮切换，选择会记住

---

## 一、EPUB 电子书

新增 `.epub` 作为第八种格式，读写双向，**只用标准库**（zipfile + xml），
没有引入任何 ebook 库——EPUB 本来就是「约定好的 zip 包」，没必要为它加依赖。

### 读

按 **spine** 顺序逐章读取。spine 是出版方定义的阅读顺序，文件名
（`ch01.xhtml` / `part-a.xhtml`）不保证顺序，按文件名排会把书读乱。

- 标题层级、列表、表格、插图都能还原
- 正文没有 `<h1>` 时，用目录（nav.xhtml 或 toc.ncx）里的标题补一个
- 包内插图按章提取，导出到 md / docx / pdf 时照常落盘或嵌入
- 书名、作者、语言带进文档模型

**容错**：OPF 缺失、目录损坏、某章解码失败，都只降级不整体失败。一本 30 章的书
第 17 章坏了，应该输出其余 29 章加一条警告，而不是让你看到「转换失败」。

### 写

按**一级标题分章**。EPUB 阅读器的目录来自章文件，整本书堆进一个 xhtml 会让
目录只剩一条、翻页卡顿。没有标题的文档退化为单章，不影响可用性。

生成的是合法的 EPUB 3：`mimetype` 是第一个条目且不压缩（否则部分阅读器直接判非法）、
`container.xml`、OPF 清单、nav 目录齐全。

### 不支持的

- EPUB 的排版样式（CSS）不保留：文字与结构过去，视觉排版由目标格式决定
- 加密 EPUB（DRM）读不了，会明确报错而不是输出乱码

## 二、转换进度

以前进度条只按「文件个数」推进：一个 300 页的扫描 PDF 从头到尾停在 0%，
界面看起来像卡死。现在：

- 进度条按**千分制**细分，显示「2 / 5　47% · 第 137/300 页」
- PDF 逐页上报、EPUB 逐章上报，其余格式在准备/写出/校验各报一次
- OCR 这种一页几秒的操作，进度条会持续移动

命令行加在交互终端下用单行覆盖刷新：

```
  3/5   62%  第 187/300 页
```

重定向到文件时自动关闭——否则日志会被进度行刷成一片。

## 三、AI eye 导读

新增开关（命令行 `--aieye`），转换完成后在产物旁多写一份 `<名称>.aieye.md`。

### 它解决什么问题

把一本书整篇塞给大模型有两个现实问题：

1. **上下文放不下**——一本 300 页的中文书约 20 万字，远超常规窗口
2. **放得下也容易「中间迷失」**——模型对开头结尾印象深，中段细节常被忽略

导读解决的是**定位**：先用几百字告诉模型「这文档有什么、大概在哪」，
再让它按需去读正文对应部分。人读书先看目录，AI 同理。

### 里面有什么

```markdown
---
aieye: 1
title: 示例文档
source: sample.pdf
source_format: pdf
target_format: md
language: zh
chars_zh: 12000
words_en: 0
paragraphs: 180
headings: 24
tables: 3
figures: 16
generated_by: AI eye 2.3.0
generated_at: 2026-01-01T00:00
---

## 一、文档概况

- **开头内容**：本章交代背景与适用范围。
- **规模**：约 12000 个汉字 / 0 个英文词，180 段，24 个标题，3 张表，16 幅插图
- **来源**：`sample.pdf`（pdf）
- **本次产物**：`md` 格式

## 二、结构地图

| 层级 | 标题 | 位置 | 摘要 |
| --- | --- | --- | --- |
| H1 | 第一章 概述 | 0% | 本章交代背景与适用范围。 |
| H2 | 1.1 背景 | 4% | 相关工作的简要回顾。 |
| H1 | 第二章 方法 | 38% | 核心流程与关键参数说明。 |
```

- **结构地图**：每个标题的层级、位置百分比、该章首段摘要
- **插图清单**：图注 + 文件名，方便对照
- **高频片段**：字面重复出现的词组，作为话题线索
- **使用建议**：上下文有限时该怎么喂

### 一条刻意的克制

**只做统计，不做语义推断。**没有分词器、没有 embedding、不调用任何模型。

原因是：分词要么带词典（体积 + 许可）要么有歧义（「研究生命起源」会被切成
「研究生 / 命 / 起源」），在导读里给出错的「关键词」比不给更糟；而本项目的
定位是离线工具，导读必须能在没有网络、没有 GPU 的机器上生成。

所以导读里只放**可验证的事实**：结构、位置、字数、图注原文、重复出现的字面串。
凡是需要「理解」才能得出的结论，一律不做。

## 四、白天 / 黑夜主题

右上角太阳/月亮按钮切换，选择会记住，下次打开还是你上次的偏好。

深浅两套是**独立调色板**而不是简单反色：

- 深色主题的强调色亮一档（`#0F6CBD` → `#4CA0E0`），否则白字压在原色上对比度不够
- 状态徽标（完成/跳过/失败）各自配了成对的前景与浅底，深色下仍能一眼分清
- 主按钮在深色下用深色文字压在亮蓝底上，而不是白字

除了 QSS，同时设置了 QPalette——只改样式表的话，QMessageBox、输入框选区
这些 Qt 内置绘制仍是白底黑字。

**主题要在建窗口之前应用**，否则会有一帧白底闪烁。

## 升级提示

- 旧版本的产物与配置完全可用；不开启新开关时输出与 2.2.0 一致
- EPUB 支持无需额外安装（标准库实现）
- AI 导读是**附加文件**，不影响主产物；关掉就不会生成
- 源码安装：`pip install "aieye[ocr]"`

## 已知限制

- EPUB 的 CSS 排版不保留，只带走文字与结构
- 加密 EPUB（DRM）无法读取
- 双栏页面（如目录页）仍按单栏从上到下读取，左右栏会交错
- 每页重复的页眉文字仍会进正文，只剔除了页码
- 表格被识别为「表格区域」后裁成图片，尚未还原成真正的行列
- AI 导读的「高频片段」是字面统计，可能出现无意义组合，仅供参考
